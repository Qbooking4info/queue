What happened, in order

Three working days. The first was spent on an outage, the second and third on features. Entries marked in amber are infrastructure rather than code; purple marks a schema change applied to the production database.

Sun 19 Oct Outage diagnosis and recovery · no commits
Infra

Every app was cut off from its own database

Reported as "I can't find what I have in my database on the app". The data was intact; the apps could not authenticate to read it. Every request was coming back 401 — Legacy API keys are disabled.

Supabase disabled the project's legacy API keys on 13 October at 08:39 UTC. The browser-facing half had already been migrated to a publishable key, but the server-side SUPABASE_SERVICE_ROLE_KEY was still a legacy JWT. Every web API route uses that key, and all four mobile apps fetch their data through those routes, so the whole query layer failed at the door.

Fixed by replacing it with a new sb_secret_ key. The dashboard offers to re-enable legacy keys, which would have fixed this in one click and must not be used: a service_role key leaked into a public repo on 26 July, and disabling legacy keys is the only thing keeping it dead.

  • 98 users, 95 appointments, 33 doctors and 54 transport requests confirmed present once access was restored.
  • Two dead legacy JWTs still sit in web/.env.local; one carries a NEXT_PUBLIC_ prefix, which would inline it into the browser bundle.
Mon 20 Oct Storage policy repair
Schema

The hospitals storage bucket accepted nothing

20261020000001_hospital_logo_uploads.sql. The bucket existed and was public-read, but had no policies at all on storage.objects, which under row-level security means every authenticated write was denied. No hospital could ever have uploaded a logo.

  • Writes limited to an active owner or admin of that specific hospital.
  • A trigger restricts a client-side update to logo_url and cover_url, so owners do not gain blanket write access to pricing or approval mode through this route.
  • Front desk deliberately excluded: they act for the hospital daily, but changing its public identity is a different kind of permission.

Verified against production: an owner passes for their own hospital, fails for another's, front desk fails, and the existing service-role settings path is unaffected.

Circular avatars that say what the thing is

Listings showed initials in a rounded square — "DMH" against Divine Mercy Hospital, which tells a patient nothing. An uploaded logo or photo now wins, and without one the fallback is an icon carrying real information, in a circular frame.

  • Doctors get a gendered or neutral person icon. Nothing guesses gender from a name.

10e0f79 New feature Schema

Locum board

A doctor posts a locum shift or permanent position at a hospital they are attached to. Every doctor in that state is notified and can accept the rate, counter with their own, or ignore it. The poster sees who replied, picks one, and only then gets their phone number.

  • Money is computed in the database. hours and total_amount are generated columns, so a client cannot post ₦5,000/hr with a ₦500,000 total. The expression wraps past midnight: 20:00 to 08:00 is 12 hours.
  • Targeting needed fixing to work at all. Every doctor's personal state is unset, so "doctors in that state" would have reached nobody. A doctor now counts as being in their own state and in the state of every hospital they are attached to, which reaches 25 of 33 doctors.
  • Ranking is cheapest first, earliest first among equals — so an accept at the asking price always outranks a counter above it. The rate is set server-side; a client that could set it could buy the top of the list.
  • Responders see only their own reply, so the board cannot be used to undercut. Phone numbers release on selection only, and the doctor is notified at that moment.

Exercised against the live database before shipping: a 08:00–17:00 shift at ₦5,000/hr produced 9 hours and ₦45,000, two doctors responded, and the list ranked the ₦5,000 accept above the ₦7,500 counter.

The Vercel build on main will fail

Five API routes build a service-role client at module scope, which kills the build when SUPABASE_SERVICE_ROLE_KEY is absent from the environment. Setting it in Vercel fixes production, which is still serving 401s; making those clients lazy would stop a missing variable taking the whole deployment down.

18 local migrations are not on the production database

Including NDPR mechanics, retention purge, signup verification and the ambulance provider tables. Fourteen further migrations exist on the remote with no local file, applied directly on 13 October. Some backend now on main depends on the missing ones. This divergence deserves an audit before production is trusted.

Two hospital-owned ambulance fleets have no operator account

Queue Hospital Ambulance Fleet and Queue OPD Ambulance Fleet hold three units between them and no ambulance_provider_admins row, so since the management move nobody can take those units on duty or assign crew. Two rows would close it.

Pull request #6 is still open and misleading
